# P1｜User Test Plan · Round 01

## 目标

验证用户能否自然走完 Golden Path，并理解“算数”的共同性、三轴状态的差异和关系边界。不是测试用户是否喜欢视觉风格。

## 样本

5–7 人，覆盖：熟悉微信小程序但不从事产品工作的人；关系类型尽量多样（朋友、伴侣、家人）。不要求两人同时参与；测试者在 Alpha 中切换模拟视角。

## 测试前

只说：“这是一个还在测试中的小程序。请边操作边说出你以为会发生什么。我不会教你正确答案。”不要预先解释 Commitment、池或算数。

## 任务

1. 想起一个你真心想和某个人以后做的事，把它说给 TA。
2. 以对方视角打开分享，决定是否让它“算数”。
3. 找到刚刚说好的那句话，并说出你认为它现在属于谁。
4. 场景：“很久没发生，但你仍然想。”选择下一步。
5. 场景：“现在准备真的去做。”选择下一步。
6. 区分三种需求：放下这一句话；暂时不在首页看到这个人；不再接收 TA 的新提议。

## 观察，不提示

- 首次点击、犹豫位置、返回行为与用户自发用词。
- 是否把“算数”理解为打卡、承诺强度或双方同意。
- 是否把池理解成垃圾箱或失败区。
- 是否认为“还想”会通知对方，或等于“来真的”。
- 是否能区分 Commitment 结束、个人收起与通信拒收。
- M01 是否让状态确认更清楚，还是遮挡/拖慢任务。

## 追问

“刚才发生了什么？”“如果一年没做，它会在哪里？”“谁能结束这件事？”“收起以后对方会知道吗？”“你最担心产品做错什么？”避免“你喜欢吗”。

## 通过线

- 至少 5/7 无帮助完成 Golden Path。
- 至少 5/7 能说明“双方都确认才算数”。
- 至少 5/7 不把池解释为删除或失败。
- 至少 5/7 首次正确区分“还想 / 来真的”。
- 至少 5/7 在三个边界场景中选择正确动作。
- 所有人都能感知分享与状态变化；无人认为 M01 在失败时也会播放。

## 必须返工

关键动作需要主持人口头解释；多数人误以为单方创建已经共享；私人信号被理解为通知；边界动作被当成删除/拉黑；Magic 掩盖状态是否成功。

## 记录模板

每位参与者记录：完成时间、首次错误、关键原话、帮助次数、每项通过/失败、隐私担忧与复盘结论。只收集测试必要信息，不记录真实关系内容到公共文档。
