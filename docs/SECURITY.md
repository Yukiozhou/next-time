# Security Baseline

## 当前范围

V3 Alpha 是本地运行的体验原型：不连接真实微信账户，不持有服务端凭据，不接收公开文件上传，也不应部署为公开生产服务。

## 本地开发规则

- 开发服务器固定监听 `127.0.0.1`；不得直接暴露到局域网或公网。
- 依赖安装使用已提交的锁文件：日常与 CI 使用 `npm ci`。
- 不运行来源不明的项目脚本，不让 Taro CLI 解压未知归档或处理不可信构建输入。
- `.env.local`、AppID 私钥、会话密钥与服务端凭据不得提交到 Git。
- 不执行 `npm audit fix --force`。当前建议会跨主要版本改变 Taro，必须通过独立升级分支验证。

## 依赖告警基线（2026-09-20）

```text
npm audit:             46 total
npm audit --omit=dev:  18 total
```

告警主要来自 Taro 4.2.1 的间接依赖，包括构建工具，以及 H5 组件链中的 `swiper` / `lodash-es`。这不等于漏洞均可由当前产品路径触发，但在正式上线前必须重新评估，不能永久接受。

## 升级策略

1. 所有 `@tarojs/*` 包保持完全相同版本，避免内部协议错配。
2. Taro 发布包含修复的稳定版本后，在独立分支整套升级。
3. 升级后执行 `npm ci`、`npm run verify`、Golden Path 回归和微信构建验证。
4. 只有在 Taro 官方兼容范围明确时，才通过 `overrides` 替换 `swiper` 等传递依赖。
5. 进入公开部署前，生产依赖中的高危与严重告警必须逐条确认可利用路径、缓解措施或升级结果。

## 上线前新增要求

- 服务端鉴权与权限检查；客户端状态不能作为真相。
- Commitment 状态转换幂等，并验证参与者身份。
- 分享令牌短期、单用途、不可枚举，日志不得记录令牌或原话正文。
- 对所有用户输入做长度和展示层转义；不接受任意 HTML。
- 建立依赖更新、密钥轮换、隐私删除与安全事件响应流程。
